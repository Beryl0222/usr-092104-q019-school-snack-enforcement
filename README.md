# 校园跨界零食处置

本仓库保存校园跨界零食处置的领域词汇、事件约定与基础校验代码，供平台协查、执法办案、检验机构与召回处置等单位统一对象身份、事件顺序和版本语义。

## 解决什么问题

开学季"可食用作业"被不同店铺标成糖果、威化糯米纸、淀粉制品甚至文具赠品，标题和公示许可证随链接变化。仅凭标题下架会误伤合规批次，也追不回流入校园周边小店的问题货。本契约把以下对象串成**证据链**：

> 平台链接 → 页面证据快照 → 经营主体 / 生产企业 / 许可证 → 产品与包装版本 → 食品分类与配料添加剂评估 → 购样封存送检留样 → 检测（初检/异议/复检）→ 流向 → 执法决定 → 整改 / 申诉 → 召回四阶段 → 学校家长通知 → 一案一档回查

## 十条领域原则（见 `contracts/event-catalog.json` 的 principles）

| 编号 | 原则 |
|---|---|
| P1 | **信封稳定**：事件交换沿用七字段信封，证据链字段全部放在 `payload` |
| P2 | **批次身份不随标题改变**：商家改名/改类目只追加 `LISTING_REVISED` 版本，`lot_ref` 不得更换 |
| P3 | **行为时标准 + 实物证据**：分类与添加剂适用性按行为发生时有效的标准版本判定；证据不足只能是 `unresolved` |
| P4 | **系统提示、人来签字**：冲突提示禁止携带签字字段；执法效力只来自 `DECISION_SIGNED` 的具备资格人员 |
| P5 | **同源关联保留依据**：跨平台关联记录许可证号/条码/批次号/配料指纹/版式哈希/人工确认；`image_only` 只能产生待确认线索，不得自动合并 |
| P6 | **抽样全程留痕**：购样→封存→移交→接收→留样双人交接、封条编号与完好性必录；复检独立出报告并回溯初检与异议 |
| P7 | **精确处置**：粒度为链接 / 门店 / 批次 / 生产企业，决定文书必须列明具体对象，不得按标题批量下架 |
| P8 | **儿童隐私**：面向学校、家长、公众的通知禁止出现购买儿童身份信息 |
| P9 | **召回四阶段**：已通知 / 已下架 / 已退回 / 无法追回，逐级登记、不得互相冲抵 |
| P10 | **一袋实物回查全链**：`CASE_SNAPSHOT_BUILT` 把该批次全部证据聚合成一案一档 |

## 目录

- `contracts/domain.schema.json`：事件信封、21 个聚合、34 个事件与受控枚举（处置粒度、冲突代码、匹配依据、交接动作、召回阶段、通知对象等）。
- `contracts/event-catalog.json`：**事件载荷契约的单一事实源**——每个事件的必填/可选载荷字段、规则编号与规则释义、原则条文。
- `data/sample.json`：一条最简中文联调样例。
- `data/sample-chain.json`："可食用作业本"一案 50 条事件的完整证据链样例（跨三平台 + 周边门店，含改名、同源人工确认、初检/异议/复检、精确处置、申诉部分采纳、召回对账、脱敏通知、归档回查）。
- `src/validator.py`：信封校验 + 按目录派生的载荷校验 + 17 条语义规则；`validate_stream` 另校验版本递增、流向序号连续、改版不改批次。
- `tests/`：契约一致性（schema 枚举与目录互校）、样例链闭环、语义规则正负样例。

## 聚合与事件一览

**主体与资质**：seller / manufacturer / food_license — 登记、许可证核验、许可证冲突提示
**链接与证据**：product_listing（取证、改版）/ listing_snapshot（页面哈希固定）/ listing_link（同源关联）
**产品身份**：product / package_version / physical_lot（实物批次，身份锚点）
**判定**：classification_assessment / ingredient_rule / conflict_tip（系统只提示）
**抽样检测**：inspection_sample（购样、封存、收样、留样）/ custody_transfer / test_report（初检、异议、复检版本）
**流向处置**：flow_trace / enforcement_action（草拟、人工签发生效）/ appeal
**召回与公开**：recall（启动、四阶段反馈、关闭对账）/ public_notice / case_snapshot

## 从一袋实物回查

`physical_lot`（批次号+包装版本+生产企业认定）是证据链中心：

- 向上：包装版式/条码 → 产品 → 生产企业与许可证 → 全部链接及其各版页面快照（含改名前后）
- 向旁：分类判定引用的行为时标准版本、配料添加剂逐项结论、同源关联的匹配依据
- 向下：购样封存与双人交接链、初检报告、异议记录、复检报告、流向各节点台账
- 处置：精确对象的草拟与签字决定、商户整改与申诉复核、召回四阶段数量、脱敏通知
- 归档：`CASE_SNAPSHOT_BUILT.included_refs` 必须能在链内逐一找到（测试强制）

## 演进规则

信封七字段与既有事件名含义不得变更；新增事件/聚合只能在 schema 枚举与事件目录中**追加**，并在目录中登记必填载荷与规则编号。校验器只执行目录已登记的规则，避免契约与代码各说各话。
